# Qt5.12.10+ 兼容重构设计

## 目标

将 `cpp_app` 重构为以 Qt 5.12.10 为最低支持版本的 C++/Qt 工程，并保证在更高版本 Qt 5 与后续升级版本上可继续使用。工程需同时满足以下约束：

- 使用 Qt 工程与 C++ 语言开发。
- 兼容 Qt 5.12.10 及以上版本。
- 兼容 Ubuntu 20.04 及以上系统与 Windows 10 及以上系统。
- 支持 32 位与 64 位操作系统构建。
- 符合中电科思仪科技股份有限公司《QYQRJ-TS-5-2022C&C++语言编码规范》要求。
- 注释率不低于 30%。

## 现状判断

当前工程同时存在 `cpp_app.pro` 与 `CMakeLists.txt`，但主构建逻辑已经偏向 CMake，且源码使用了 Qt Widgets、Qt Network、UHD、NI-VISA 和 Python 预处理桥接。现状不适合直接把 Qt6 专属写法当成唯一基线，否则会把 Qt5.12.10 兼容目标锁死。

因此本次重构应当采用“单基线兼容”策略：

- 以 Qt 5.12.10 为最低 API 基线。
- 只使用 Qt 5.12.10 已支持的模块和写法。
- 对少量高版本差异点使用版本宏分支。
- 避免引入 Qt6 专属 API、Qt6-only CMake 逻辑、Qt6-only 行为假设。

## 设计原则

1. **最低版本优先**：所有新增代码先按 Qt 5.12.10 验证，再向上兼容更高版本。
2. **构建与源码解耦**：构建系统负责找到 Qt、UHD、VISA；源码只处理可移植逻辑。
3. **平台中性**：Windows 与 Ubuntu 的差异放在构建脚本和路径适配层，不扩散到业务逻辑。
4. **位宽可配置**：32 位与 64 位差异通过 toolchain、库路径、平台判断处理，不在业务代码中硬编码。
5. **规范先行**：公共接口、关键流程、边界条件、平台差异点补足注释，确保文档性代码比例满足要求。

## 推荐实现路径

### 1. 构建入口整理

保留 `CMakeLists.txt` 作为主入口，`cpp_app.pro` 仅作为兼容参考或过渡入口，不作为主要维护对象。原因是当前工程已经有较完整的 CMake 组织方式，服务、测试、工具目标都已拆分，继续以 CMake 统一更利于多平台和多位宽控制。

### 2. Qt 版本兼容层

新增一个轻量兼容头文件，例如 `src/app/QtCompat.h`，集中放置版本判断和跨版本 API 适配。适配内容只保留必要项，例如：

- `QT_VERSION_CHECK` 分支。
- Qt 5.12.10 与更高版本之间的轻微 API 差异。
- 避免把兼容逻辑散落在业务类中。

原则是“少而集中”，不做大而全封装。

### 3. 源码层收敛

对现有源码做一次兼容审视，重点检查这些点：

- 是否使用了 Qt6-only 类型或接口。
- 是否依赖 `QStringLiteral`、`QVector`、`QList` 等在 Qt5.12 中稳定支持的基础设施。
- 是否有 C++17 写法超出旧编译器可接受范围。
- 是否存在仅在 Windows 下有效的路径拼接、编码或进程启动假设。
- 是否有 UI 类把平台、路径、业务逻辑混在一起。

### 4. 平台与位宽支持

构建与文档中明确区分：

- Windows 10+：MSVC 工具链、Qt5.12.10+、UHD、NI-VISA。
- Ubuntu 20.04+：GCC/Clang 工具链、Qt5.12.10+、UHD、必要的 VISA 或替代实现。
- 32/64 位：通过 Qt 套件、UHD/VISA 目标库、构建参数和部署脚本控制。

这里不把 32 位与 64 位写成两套代码，而是写成同一套源码、不同构建配置。

### 5. 编码规范与注释率

按《QYQRJ-TS-5-2022C&C++语言编码规范》做两类工作：

- 统一命名、空白、结构、函数长度、职责边界。
- 对复杂流程、平台差异、协议解析、文件格式和线程/进程交互补充说明性注释。

注释率要求不适合靠空注释堆出来，应优先覆盖：

- 模块职责说明。
- 关键参数含义。
- 协议偏移、文件格式、状态转换。
- 平台分支理由。

## 影响范围

预计主要影响：

- `CMakeLists.txt`
- `cpp_app.pro`
- `src/app`
- `src/services`
- `src/ui`
- `tests`
- 文档：`README.zh-CN.md`、`requirements.md`

不建议扩大到未涉及的工具脚本或数据目录，除非它们直接阻碍 Qt5.12.10 兼容。

## 验收标准

1. 工程可在 Qt 5.12.10 及以上版本下构建。
2. Windows 10+ 与 Ubuntu 20.04+ 均有明确构建和运行说明。
3. 32 位与 64 位构建路径清晰，不依赖单一位宽硬编码。
4. 关键源码没有 Qt6-only 绑定。
5. 规范性注释覆盖复杂逻辑，满足项目注释率要求。
6. 测试和运行文档与实际构建方式一致。

## 风险

- 现有工程已经偏向 Qt6/CMake，回落到 Qt5.12.10 基线时，部分 API 可能需要逐处修正。
- UHD、VISA、Python 预处理桥接在 Linux 上的部署差异需要额外验证。
- 32 位支持可能受第三方 SDK 供给限制，尤其是 UHD 和 VISA 的可用库位宽。

## 后续实施顺序

1. 先改构建与兼容层。
2. 再修源码中的版本和平台差异点。
3. 最后补文档、测试和注释。
